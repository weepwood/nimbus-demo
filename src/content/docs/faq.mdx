## 为什么发布到 GitHub Pages 后出现 404？

本项目的页面路径包含部署子目录 `/nimbus-demo/`。如果创建的是新的仓库，请修改 `astro.config.ts` 的 `base` 为实际仓库名，或在使用自定义域名时将其改为 `/`。

Nimbus 会为 MDX 中的站内链接自动添加 Astro 的 `base`，不要在原始文档中手动写 `/nimbus-demo` 前缀。

## 为什么搜索没有结果？

搜索使用 Pagefind。它在 `pnpm build` 完成时建立静态索引。在开发模式下无法保证搜索行为与生产环境完全一致，请执行：

~~~bash
pnpm build
pnpm preview
~~~

然后从预览站点使用 Ctrl + K（macOS 为 ⌘ + K）进行测试。

## 新建文档如何进入导航？

在 `src/content/docs/` 下添加 `.mdx`，填入必需的 frontmatter，构建时 Nimbus 会自动生成侧边栏。示例见 [文档写作](/writing-pages/)。

## 如何在 MDX 中生成正确的站内链接？

在 Nimbus 的 MDX 文档中，只需编写逻辑上的站内路径。Nimbus 会在渲染时自动添加部署前缀：

~~~mdx
[快速开始](/quickstart/)
~~~

对于独立的 `.astro` 组件或页面，可以从 `@cloudflare/nimbus-docs/runtime` 导入 `withBase`，手动将逻辑路径转换为部署路径。不要为 MDX 链接再次调用 `withBase`。

## 如何修改品牌和页面外观？

- UI 主设计令牌：`src/styles/globals.css`
- 演示首页样式：`src/styles/demo.css`
- 顶部栏：`src/components/Header.astro`
- 通用组件：`src/components/ui/`

不建议直接修改 `node_modules` 中的 Nimbus 代码。

## 如何生成属于自己的站点配置？

打开 [项目配置生成器](/configurator/)，填写站点 URL、仓库地址、子路径、语言等信息，然后复制或下载生成的 `astro.config.ts`。

## 如何检查发布产物是否完整？

~~~bash
pnpm run check
~~~

此命令依次执行类型检查、Astro 静态构建、Nimbus 文档校验和生成后站点链接检查。

## 有额外组件可以安装吗？

可以。Nimbus 的官方 Registry 提供可选择安装的组件和能力。参考 [官方 Registry](https://nimbus-docs.com/registry)。

## 阅读清单的数据存在哪里？

文档页底部的收藏按钮会把页面标题、路径和收藏时间存入浏览器 `localStorage`。它不会发送给 GitHub 或任何后端，因此不同设备之间不会自动同步。

可以在 [阅读清单](/reading-list/) 中移除或者清空收藏。详见 [阅读工具说明](/reading-list-guide/)。

## 为什么 API 工作台返回固定数据？

当前的 [API 请求工作台](/api-lab/) 调用的是真实网络 GET 请求，但访问的是预渲染静态 JSON，故返回固定的公开模拟数据。完整字段和行为记录在 [API 参考](/api-reference/) 与 [OpenAPI 规格](/openapi.json)。

## 如何提出文档问题？

文档底部提供“反馈问题”，它会打开 GitHub Issue 创建页面，并预填当前页面标题和链接。不会自动发送消息，用户需要自行确认并提交。
