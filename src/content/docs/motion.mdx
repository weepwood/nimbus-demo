动效的目的不是让页面持续运动，而是帮助读者理解界面的反馈、层级和状态变化。Nimbus Studio 统一使用轻量 CSS 过渡、原生浏览器 API 与 Astro 生命周期，不需要引入额外动画库。

## 动效节奏

| 类型 | 时长 | 使用场景 |
| --- | --- | --- |
| 快速反馈 | **140ms** | 按钮、链接、图标反馈 |
| 常规过渡 | **220ms** | 菜单、搜索弹窗、标签页 |
| 空间进入 | **340ms** | 进入视口的内容块 |

~~~css title="src/styles/motion.css"
:root {
  --nd-motion-fast: 140ms;
  --nd-motion-normal: 220ms;
  --nd-motion-slow: 340ms;
  --nd-ease-out: cubic-bezier(.22,1,.36,1);
  --nd-ease-standard: cubic-bezier(.2,.7,.2,1);
}
~~~

## 导航与搜索

- 首页预览中的搜索按钮会打开真正的 Nimbus SearchDialog，而不是静态装饰。
- 顶部移动菜单采用原生 `details`：可以点击菜单外部关闭，也可以按 Escape 并将焦点返回开关。
- 标签页使用 Nimbus 的 `Tabs`，动画只作用于可见内容；键盘选择和 ARIA 语义不变。
- 在长文中滚动后会出现“返回顶部”，按 Enter/Space 即可操作。

## 可中断的异步交互

API 请求必须与界面选择保持一致。切换端点时，旧请求会被取消且不再影响新端点；手动点击“取消”也会提供明确反馈。

<Steps>
  <Step title="开始请求">
    显示加载状态、禁用重复发送，并开放“取消”按钮。
  </Step>
  <Step title="接口切换">
    调用 `AbortController.abort()` 中止正在运行的请求，随后清除旧状态。
  </Step>
  <Step title="完成或失败">
    只允许当前有效请求更新状态、耗时和响应，错误信息不应被旧结果覆盖。
  </Step>
</Steps>

## 减少动态效果

<Aside type="tip" title="系统偏好始终优先">
  当操作系统设置了 `prefers-reduced-motion: reduce`，页面直接切换状态，不执行入场动画；Playground 的重播按钮只反馈说明，不启动动画。
</Aside>

~~~css
@media (prefers-reduced-motion: no-preference) {
  .nd-read-action {
    transition: background 140ms, transform 140ms;
  }
}

@media (prefers-reduced-motion: reduce) {
  .nd-read-action { transition: none; }
}
~~~

## 为什么使用 CSS 与原生 API？

CSS 在短时 hover / transition 上无需引入额外依赖，Web Animations API 可随时取消/重播；滚动触发通过 `IntersectionObserver` 在视口外才设置入场状态，避免 JS 禁用时页面被隐藏。阅读进度使用 `transform:scaleX()` 更新，减少布局开销。
